# Review and sharing

The authoritative coding is in the run's `coding/*.json`. Generated TSV/JSON/Markdown files are snapshots, not editable databases feeding the analysis. Review the source excerpt in context before changing a decision.

1. Review uncertain attribution, extraction warnings and excluded/empty cases first. Check every apparent duplicate and every merged case.
2. Review OPP/QUAL, strong support, suggestions and outside-framework material, then sample other cases and apparent agreement. The queue contains all unreviewed units, so it supports a full review if resources permit.
3. Record reviewer, date, old/new decision and rationale in `review_log`. Update the unit's review status; do not silently replace source excerpts. Adjudicate disagreements explicitly.
4. Run validation, revise the narrative if conclusions change, and build a new snapshot. Check the updated support and sensitivity tables. Save previous outputs.
5. A second AI pass is not an independent human coder. If reliability matters, commission a genuinely independent sample coding, discuss disagreements and document the resulting protocol changes. This toolkit does not calculate intercoder reliability automatically.

The main report is for discussion; the statement register supports audit; the revision register supports framework development. All may contain identifiable or sensitive details, including the narrative. A case ID is not anonymisation. Prepare and review a disclosure-controlled briefing before sharing outside the authorised research group. The toolkit does not send files, emails or messages.
