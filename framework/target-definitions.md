# Target definitions

Reusable coding boundaries. X and O codes are inherited candidate vocabulary; they are not evidence about the new interviews. Add genuinely new targets and explain their boundaries in the run codebook.

## Deductive targets

| Code | Target | Boundary |
|---|---|---|
| T1 | Cultural/societal value | Heritage and societal understanding; broader social benefit is retained but flagged where it extends the narrow slide definition |
| T2 | Scientific value | Scientific understanding and advancement; verification/reproducibility may extend the slides' conceptual-framework emphasis |
| T3 | Market value | Economic benefit, commercialisation; storage expenditure alone is not market value |
| T4 | Replacement value | Production/recreation resources and irrecoverability; ongoing storage is a separate cost issue |
| T5 | Compliance value | Consequences of failing ethical, legal or contractual obligations; security is not automatically reducible to compliance |
| I1 | Originality/uniqueness | Novelty or uniqueness of data |
| I2 | Reliability | Appropriate and quality-controlled collection; distinguish methodological credibility from prestige |
| I3 | Representativeness | Adequacy of coverage for a research question, not simply population representativeness |
| I4 | Data organisation/standardisation | Structure, organisation, usable formats |
| I5 | Metadata richness/standardisation | Documentation, metadata standards and provenance where explicitly documented |
| E1 | Relevance | Fit to a purpose or need |
| E2 | Demand | Stakeholder demand; distinguish numbers from intensity or criticality |
| E3 | Exclusivity | Scarcity/abundance relative to demand in the slides; restricted access is an alternative reading to flag |
| E4 | Innovation/technological compatibility | Available technology and exploitation; do not silently equate this with all innovation |
| E5 | Accessibility | Ability and ease of access; openness is a possible condition, not a synonym for value |
| E6 | Reputation of source | Trust in producer; distinguish from career/status benefits accruing to a producer |
| F-TYPES | Value-type scheme | Explicit appraisal of the list as a whole |
| F-FACTORS | Factor scheme | Explicit appraisal of the factors as a whole |
| F-INTRINSIC | Intrinsic factor group | Appraisal of this group, not the proposition that data possess philosophical intrinsic value |
| F-EXTRINSIC | Extrinsic factor group | Appraisal of this group |
| F-STRUCTURE | Relations and distinctions | Type/factor overlap, group boundaries, benefit versus cost/obligation |
| F-CONTEXT | Context dependence | Role of research question, use setting or perspective in valuation |
| F-INHERENT | Value without context | Additional analytical target for Q11's philosophical question; not equivalent to F-INTRINSIC |
| F-UTILITY | Usefulness of a framework | Expected practical benefit; does not validate the five types or eleven factors |

Suggestions have an independent field: `new_value`, `new_factor`, `refine_definition`, `restructure`, `operationalise` or `none`. Only an actual proposal receives this field. A further field distinguishes an interviewee proposal from a researcher reflection or uncertain attribution. Proposed new labels do not become settled categories merely because somebody suggested them.
